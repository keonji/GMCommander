# GMCommander

Аддон для World of Warcraft 3.3.5a (WotLK) — панель GM-команд для
сервера [AzerothCore](https://github.com/azerothcore/azerothcore-wotlk).

Воскресить, выдать золото, поднять уровень, ускориться, прописать
шмотку, выучить профессию, прыгнуть в рейд, выдать или завершить
квест — кнопками, без набора команд в чате.

**Серверный модуль не требуется.** Аддон отправляет те же команды, что
вы набрали бы вручную.

---

## Что умеет

**Игрок.** Воскресить игрока, оживить NPC, убить цель, призвать игрока
к себе, прыгнуть к нему, починить экипировку, вытащить из текстур,
открыть карту, поднять навыки. Переключатели режимов — бессмертие,
полёт, режим ГМ, мгновенный каст, без откатов, без затрат ресурса,
хождение по воде, все точки полётов. Включённые подсвечиваются.

Золото кнопками 10/100/1000/5000 или своей суммой. Скорость ×1/×3/×5/×10
или своим значением. Уровень — шагами ±1/±5/+10, сразу до 80 или точным
значением.

Команды, которым нужна цель, помечены: если выделения нет либо оно не
того типа (NPC там, где нужен игрок), аддон скажет об этом сам, а не
отправит команду впустую.

**Телепорт.** Города, подземелья и рейды с русскими названиями,
сгруппированные по дополнениям, с подписью уровня или размера рейда.
Поиск по названию и избранное — часто нужные точки закрепляются
звёздочкой. Отдельно — прыжок к тому, кто выдаёт квест, и к тому, кто
его принимает, по ID квеста. Кнопка «Назад» возвращает на прежнее место.

**Предметы.** Выдача по ID или Shift+кликом по предмету — аддон
перехватывает вставку ссылки и подставляет ID сам. Поиск по названию
через базу сервера: результаты приходят кликабельными ссылками.
Восемь готовых наборов — сумки, еда, зелья, реагенты, маунты, камень
возвращения, отмычки. История последних выданных предметов — повторить
одним нажатием.

**Квесты.** Выдать, завершить, наградить, убрать, показать состояние —
по ID или по ссылке. Кнопка «Выдать, завершить и наградить» проходит
квест целиком. Отдельный блок для выдачи предметов, которые квест
требует. Поиск квеста по названию через базу сервера.

**Обучение.** Четырнадцать профессий, каждая учится сразу со всеми
рангами до грандмастера. Массовое обучение: все заклинания класса, все
таланты, всё у тренера, все языки, все рецепты. Отдельное заклинание по
ID, поиск по названию, сброс талантов и заклинаний.

**Настройки.** Куда применять команды — к цели или всегда к себе,
подтверждения, эхо в чат, масштаб, прозрачность, пауза между командами.

**Полоса быстрых действий.** Шесть иконок поверх интерфейса.

## Установка

1. Скачайте репозиторий.
2. Скопируйте папку `GMCommander` (внутреннюю, где лежит
   `GMCommander.toc`) в `World of Warcraft/Interface/AddOns/`.
3. Путь должен получиться таким:
   `Interface/AddOns/GMCommander/GMCommander.toc`
4. Перезапустите клиент. Если аддон не виден — включите «Загружать
   устаревшие аддоны» на экране выбора персонажа.

Нужны права GM на аккаунте. В консоли сервера:

```
account set gmlevel ИМЯ_АККАУНТА 3 -1
```

После этого перезайдите в игру.

## Команды чата

| Команда | Действие |
|---|---|
| `/gm` | открыть или закрыть панель |
| `/gm tp Даларан` | телепорт по русскому или английскому названию |
| `/gm item 6948 5` | выдать предмет |
| `/gm gold 500` | выдать золото |
| `/gm lvl 80` | поднять до уровня |
| `/gm speed 5` | скорость бега, полёта и плавания |
| `/gm q add 1234` | квест: add / complete / reward / remove / status |
| `/gm quest 1234` | прыжок к выдающему квест |
| `/gm bar` | показать или скрыть полосу |
| `/gm modify speed 3` | любая GM-команда без точки |
| `/gm help` | список команд |

## Как это устроено

GM-команды в 3.3.5a — это обычные сообщения чата, начинающиеся с точки:
сервер перехватывает их в `ChatHandler` до того, как текст попадёт в
канал. Отдельного протокола нет, и аддон ничего не «взламывает» — он
печатает за вас.

Отсюда единственное инженерное ограничение: на чат действует
антиспам-защита сервера. Набор предметов или обучение четырнадцати
профессиям — это десяток команд подряд, и отправленные одним кадром они
частично потерялись бы. Поэтому в `Comm.lua` очередь с паузой
(по умолчанию 0.3 с).

### Что проверено по исходникам

Все команды сверены с `src/server/scripts/Commands/cs_*.cpp` (июль 2026),
а не взяты из памяти. Несколько находок, повлиявших на реализацию:

**Уровень задаётся приростом, а не итогом.** `.character levelup N`
делает `newlevel = oldlevel + N` (`cs_character.cpp:775`). Поэтому
кнопка «До 80» сначала читает текущий уровень цели и считает разницу
сама.

**Команды «дать опыт» не существует.** Во всём наборе `cs_*.cpp` нет
ничего, что выдавало бы опыт напрямую — только уровни целиком. Об этом
прямо написано в интерфейсе, чтобы её не искали.

**К цели квеста прыгнуть нельзя.** Координат целей квеста у клиента
нет. Зато сервер умеет прыгать к тому, кто квест выдаёт, и к тому, кто
принимает — `.go quest starter|ender <id>` (`cs_go.cpp:520`). Это и
сделано.

**Профессии учатся с ID первого ранга.** `.learn <id> all` проходит всю
цепочку рангов (`cs_learn.cpp:70`), поэтому используется ID ранга
«ученик» — исходные значения из Классики. ID грандмастерских рангов
пришлось бы брать из клиентского DBC, которого в репозитории сервера
нет, то есть проверить их локально было бы невозможно. Все четырнадцать
ID подтверждены по `trainer_spell`.

**Имена телепортов — из `game_tele`.** В таблице 1988 точек; аддон
использует 70 популярных. Опечатка в имени не вызвала бы ошибки — она
просто молча не сработала бы в игре, поэтому сверка вынесена в
отдельный скрипт (см. ниже).

**`.die` не убивает вас без цели.** Команда требует выделения любого
юнита и без него просто отвечает «выберите персонажа или существо»
(`cs_misc.cpp:1211`). Аддон проверяет выделение до отправки.

**Воскрешение игрока и оживление NPC — разные команды.** `.revive`
работает по игроку, `.respawn` — только по мёртвому существу
(`cs_misc.cpp:2728`). В интерфейсе это две отдельные кнопки.

**`.summon` принимает только игрока** (`cs_misc.cpp:974`), поэтому с
выделенным NPC аддон её не отправляет.

### Данные о квестах и предметах

Клиент 3.3.5a не знает ни названий квестов вне журнала, ни их целей,
ни того, какие предметы для них нужны — всё это живёт в базе сервера.
Есть два пути:

**Через сервер.** `.lookup quest`, `.lookup item` и `.lookup spell`
отвечают в чат кликабельными ссылками. Работает всегда, но требует
ручного клика по результату.

**Через Questie.** Если установлен
[Questie-335](https://github.com/divial28/Questie-335), рядом уже лежит
полная база WotLK (~13 МБ: квесты, предметы, NPC, объекты) с целями и
координатами. GMCommander читает её напрямую: показывает название
выбранного квеста и выдаёт все нужные ему предметы одной кнопкой.

Связка полностью опциональна — в `.toc` нет зависимости, проверка идёт
в рантайме. Без Questie аддон работает как обычно, просто без подсказок.

### Чего аддон не делает

Он не обходит права: доступ к каждой команде решает сервер по уровню
аккаунта. Если команда не срабатывает молча — не хватает прав.

## Разработка

Прогон на эмуляции клиентского API, без запуска WoW:

```bash
lua tests/run.lua
```

174 проверки: загрузка всех файлов в порядке `.toc`, построение
интерфейса, переключение вкладок, формат и троттлинг команд, подсчёт
прироста уровня, различение игрока и NPC, требования к выделению у
каждой команды, границы скорости, действия над квестами, разбор ссылок
предметов, квестов и заклинаний, история выдачи, поиск телепорта по
русскому названию, слэш-команды, связка с Questie в обоих состояниях.

Отдельно проверяется вёрстка: тест считает правый край каждого элемента
и падает, если что-то вылезает за окно.

Сверка имён телепортов с реальной базой сервера — отдельно, потому что
дамп есть не на всякой машине:

```bash
lua tests/check_tele.lua ~/Projects/AzerothCore/data/sql/base/db_world/game_tele.sql
```

### Команды в виде духа

Мёртвому персонажу клиент запрещает писать в `/say` — команда до
сервера просто не доходит. При этом самому серверу канал безразличен:
GM-команду он перехватывает по точке в начале строки
(`ChatHandler.cpp:307`) — причём **раньше** проверки на смерть
(`ChatHandler.cpp:376`).

Шёпот в виде духа клиент разрешает, поэтому в мёртвом состоянии аддон
переключается на `/whisper`. По умолчанию шепчет вам самому: получатель
существует всегда, а сообщение всё равно перехватывается сервером и в
чате не появляется. Другое имя можно задать в настройках.

### Символы в интерфейсе

Русский клиент 3.3.5a выводит текст шрифтом с кодировкой CP1251.
Символы, которых в CP1251 нет, рисуются как случайные буквы: знак
умножения `×` (U+00D7) превращается в «Ч», стрелка `→` тоже. Поэтому
множитель скорости пишется как `x3`, а крестик закрытия — латинской
`X`. Тире, кавычки-лапки и middot в CP1251 есть и работают.

Проверка вынесена в отдельный скрипт:

```bash
lua tests/check_glyphs.lua GMCommander
```

### Структура

```
GMCommander/
  GMCommander.toc      порядок загрузки
  GMCommander.lua      инициализация и действия
  Modules/
    Compat.lua         заплатки под 3.3.5a (SetShown и прочее)
    Config.lua         SavedVariables
    Const.lua          команды, профессии, точки телепортации
    Comm.lua           очередь отправки
    Theme.lua          палитра и отрисовка
    Widgets.lua        кнопки, слайдеры, диалоги
    UI_Main.lua        каркас окна и вкладки
    UI_Player.lua      вкладка «Игрок»
    UI_Teleport.lua    вкладка «Телепорт»
    QuestieBridge.lua  необязательное чтение базы Questie
    UI_Items.lua       вкладка «Предметы»
    UI_Quests.lua      вкладка «Квесты»
    UI_Learn.lua       вкладка «Обучение»
    UI_Settings.lua    вкладка «Настройки»
    Bar.lua            полоса быстрых действий
    Slash.lua          команды чата
tests/
  wow_stub.lua         эмуляция API клиента
  run.lua              прогон
  check_tele.lua       сверка телепортов с game_tele
```

Новая вкладка добавляется файлом `UI_*.lua` с
`ns.RegisterPage{ title, build, refresh }` и строкой в `.toc`.

Ядро отрисовки (`Theme.lua`, `Widgets.lua`, `Compat.lua`) общее с
[BotCommander](https://github.com/keonji/BotCommander).
